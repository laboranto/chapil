# 차필 UI 개편 설계

원 계획서: `docs/client/20260831_UI 개편 계획.md`
작성일: 2026-08-31

## 1. 개요 / 목표

기존 그래픽 톤(카드, 색, 여백)은 유지하되 레이아웃과 페이지 구성을 바꾼다.

1. 고정 헤더(topbar)를 리스트/홈에서 제거
2. 내비게이션을 4개(홈·주유·정비·기타) → 3개(홈·기록·설정)로 축소
3. 주유·정비·기타 리스트를 "기록" 한 페이지로 통합 + 필터 탭(필터 기능 MVP)
4. 주유·정비·기타 입력 양식을 세그먼트 탭으로 통합(신규 입력 한정)
5. 아이콘을 커스텀 라인아트 → Noto Emoji(흑백) 추출본으로 전면 교체하고, 재생성 파이프라인을 repo에 둔다

비목표(YAGNI): 필터 다중선택, 정렬 옵션, 검색, 태그, 리스트 가상화, 기존 경로 하위호환.

## 2. 아이콘 시스템

### 2.1 추출 파이프라인

- `frontend/scripts/NotoEmoji-Regular.ttf` — 폰트 vendoring (약 2MB, OFL-1.1). 라이선스 파일 `frontend/scripts/NotoEmoji-OFL.txt` 동봉.
- `frontend/scripts/extract-emoji.py` — `fonttools`로 지정 글리프만 뽑아 SVG로 저장.
  - 이모지 목록은 스크립트 상단 `TARGETS` dict (`{이름: 코드포인트}`).
  - 각 글리프: `BoundsPen`으로 실제 bbox → 정사각 viewBox(+8% 패딩)로 정규화, `transform="scale(1 -1)"`로 y축 뒤집기, `<path fill="currentColor">` 단일 경로.
  - 출력 경로는 인자로 받음: `python scripts/extract-emoji.py src/assets/symbols`
- `frontend/package.json` scripts에 `"icons": "python scripts/extract-emoji.py src/assets/symbols"` 추가.
- 의존: 개발 환경에 Python + `fonttools`. `README` 또는 스펙에 명시. 빌드(`vite build`)에는 개입하지 않음 — 생성된 SVG는 커밋된다.

## 4. Home 화면

### 4.1 구조 (위→아래)

1. **정체성 블록** — 프로필 사진(원형, 탭 → 사진 모달) 왼쪽 + 오른쪽에:
   - 1행: 차량명 `{car_brand} {car_model}` (제목, 굵게)
   - 2행: `{car_plate} · {연식} · {car_type 라벨} · {car_fuel 라벨}` (작은 회색 텍스트, 값 없는 항목은 건너뜀)
   - 번호판 전용 그래픽 요소(`.car-profile h1`) 폐지.
2. **요약 — 가로 줄 타일 3개** (세로 스택). 각 타일: 좌측 라벨(회색) / 우측 `값`(굵게) + `단위`(작은 회색).
   - `한 달 지출` · `{cost_last_30d}` 원
   - `평균 {economyLabel}` · `{avg_economy || '-'}` `{economyUnit}`
   - `총 주행거리` · `{latest_odometer || '-'}` km
3. **최근 기록** — `section-header "최근 기록"` + 통합 카드 리스트(최신순 10개, 필터 없음). 각 카드 좌측에 타입 이모지(⛽/🔌/🔧/📦). 기록이 없으면 헤더째 숨김.
4. 하단 푸터("오늘도 안전운전 하세요" + 버전) **삭제**.

### 4.2 유지되는 것

- 프로필 사진 업로드/크롭/편집/삭제 모달(`carThumb`, `carImageModal`, `cropModal`, `react-easy-crop`) — 로직 그대로, 위치만 정체성 블록으로.
- 설정 진입점(gear NavLink) 제거 — 설정은 BottomNav로.
- 로딩 상태(`data === null`) 처리 유지.

### 4.3 최근 기록 카드

타입별 표현이 다르므로 카드 컴포넌트를 타입별로 유지(§6.3과 공유):

- 주유/충전: 날짜 · 주행거리(+구간) / 리터 · 단가 / 연비 뱃지 / 금액
- 정비: 항목명 / 날짜 · 주행거리 / 금액
- 기타: 항목명 / 날짜 (· 주행거리) / 금액 / 메모

Home에서는 좌측 타입 이모지를 추가로 붙인다. `MoreMenu`(수정/삭제)는 Home 카드에는 **없음**(기록 페이지에만).

## 5. 데이터 계층 (api.js / pagination.js)

### 5.1 통합 최근 기록

`api.getRecentRecords()` 신설:

```sql
SELECT id, date, 'fuel' AS src, amount, odometer, interval_km, liters, unit_price, fuel_economy, NULL AS item FROM fuel
UNION ALL
SELECT id, date, 'maintenance' AS src, amount, odometer, NULL, NULL, NULL, NULL, item FROM maintenance
UNION ALL
SELECT id, date, 'other' AS src, amount, odometer, NULL, NULL, NULL, NULL, item FROM other
ORDER BY date DESC, src ASC, id DESC
LIMIT 10
```

`getDashboard`는 `recent_fuel`/`last_maintenance`/`last_other` 대신 이 결과를 `recent`로 반환. 요약 통계 쿼리(`cost_last_30d`, `avg_economy`, `latest_odometer`, `total_days`)는 현행 유지.

### 5.2 통합 리스트 페이지네이션

`api.getRecordsPage({ cursor = null, filter = null, limit = PAGE_SIZE })`:

- `filter ∈ {null, 'fuel', 'maintenance', 'other'}`.
- `filter`가 있으면 해당 테이블 단일 조회(기존 `buildKeysetQuery` 재사용, 커서 `(date, id)`).
- `filter`가 `null`이면 3테이블 `UNION ALL` + `src` 컬럼, 정렬 `date DESC, src ASC, id DESC`, 커서 `(date, src, id)`.
- `src` 정렬 우선순위 고정: `fuel < maintenance < other` (SQL에서 리터럴 문자열 비교로 성립).

`pagination.js`:

- `buildKeysetUnionQuery(cursor, limit)` 신설 — UNION 본문 + `WHERE (date < ?) OR (date = ? AND src > ?) OR (date = ? AND src = ? AND id < ?)`.
  - 주의: `date`/`id`는 내림차순, `src`는 오름차순이므로 비교 방향이 섞인다. 위 조건식이 정확한 형태다.
- `nextCursorFrom`은 UNION 결과에 대해 `{ date, src, id }`를 반환하도록 확장(마지막 행 기준). 단일 테이블 경로는 `{ date, id }` 유지.

### 5.3 기존 함수 정리

- `getFuelPage`, `getMaintenancePage`, `getOtherPage` 삭제 → `getRecordsPage`로 흡수.
- `getFuel`, `getMaintenance`, `getOther`(전체조회, 폼 계산·통계용)는 **유지**.
- `createFuel`/`updateFuel`/`deleteFuel` 등 CRUD는 변경 없음.

### 5.4 usePaginatedList

`fetchPage` 시그니처가 `({cursor}) => ({rows, nextCursor})`로 이미 커서 불투명(opaque) 처리 → 훅 자체는 수정 불필요. `Records.jsx`가 `filter`를 클로저로 넘기고, 필터 변경 시 리스트를 리셋(훅을 `key`로 재마운트하거나 리셋 함수 추가).

- 결정: **`Records.jsx`에서 `filter`를 `key`로 사용해 `usePaginatedList` 소비 컴포넌트를 재마운트**. 훅 무수정, 가장 단순.

## 6. 기록 페이지 (`pages/Records.jsx`)

### 6.1 레이아웃

1. **sticky 필터 탭** (`SegmentTabs`, 상단 고정). 3개: `{fuelTerm}` / `정비` / `기타`.
   - 선택 없음(`null`) = 전체. 탭 하나 누르면 해당 필터. 선택된 탭 다시 누르면 `null`로 복귀.
   - 상태는 페이지 로컬. 페이지 재진입 시 항상 `null`로 초기화(세션 유지 안 함).
2. **카드 리스트** — `usePaginatedList(fetchPage)` 기반 무한 스크롤. `key={filter ?? 'all'}`로 재마운트.
   - 카드는 타입별 렌더(§6.3). 전체 모드에서도 좌측 타입 이모지 표시. 필터 모드에서는 이모지 생략(선택). → 결정: **항상 표시**(일관성, 코드 단순).
   - 각 카드에 `MoreMenu`(수정 → 해당 타입 편집 라우트, 삭제 → confirm 후 `removeRecord`).
3. **플로팅 `+` 버튼**(`.btn-add`) → `/records/new`.

### 6.2 SegmentTabs 컴포넌트 (`components/SegmentTabs.jsx`)

```
<SegmentTabs
  options={[{key, label, icon}]}
  value={string|null}
  onChange={(key) => void}      // 같은 key 재선택 시 필터에서는 null 전달, 양식에서는 무시
  allowDeselect={boolean}        // 필터=true, 양식=false
/>
```

필터와 양식 래퍼가 공유. 순수 프레젠테이션(상태는 부모).

### 6.3 카드 컴포넌트

기존 `FuelList`/`MaintenanceList`/`OtherList`의 카드 마크업을 각각 `components/records/FuelCard.jsx` / `MaintenanceCard.jsx` / `OtherCard.jsx`로 추출.

- props: `record`, `showTypeIcon`(bool), `onEdit`, `onDelete`(둘 다 optional — Home은 안 넘김).
- `FuelCard`는 `economyUnit`이 필요(현재 `FuelList`가 `useSettings`로 조회) → 카드 내부에서 `useSettings` 사용.
- 데이터 이상 뱃지(주행거리 오류/연비 표시 조건) 로직은 `FuelCard`로 이동.

`Records.jsx`와 `Home.jsx`가 `record.src`(또는 Home의 `recent[i].src`)로 분기하여 해당 카드 렌더.

### 6.4 삭제된 파일

`pages/FuelList.jsx`, `pages/MaintenanceList.jsx`, `pages/OtherList.jsx`.

## 7. 기록 양식 (`pages/RecordForm.jsx`)

### 7.1 동작

- `/records/new`에서만 사용. 상단: 고정 액션바(✕ / 저장) + `SegmentTabs`(주유·정비·기타, `allowDeselect={false}`, 기본 `fuel`).
- 탭 아래에 기존 `FuelForm` / `MaintenanceForm` / `OtherForm`을 **그대로** 렌더(각각 독립 모듈). 래퍼가 활성 탭에 맞는 컴포넌트를 마운트.
- **탭 전환 시 dirty 확인**: 현재 양식이 초기값에서 변경되었으면 `window.confirm('입력 중인 내용을 버리고 이동할까요?')`. 취소 시 탭 유지.
- 저장·취소 버튼은 활성 양식의 것을 호출. 래퍼가 활성 양식의 submit/cancel 핸들러에 위임.

### 7.2 기존 양식 컴포넌트 수정

`FuelForm`/`MaintenanceForm`/`OtherForm`:

- 현재 각자 `topbar`(✕/저장)와 `navigate('/fuel')` 등을 갖고 있음. → topbar 마크업 제거, 성공/취소 시 이동 경로를 `/records`로, 그리고 **신규 모드에서는 래퍼가 액션바·네비게이션을 관장**하도록 리팩터.
  - 방식: 각 폼이 `onDirtyChange(bool)`, `submitRef`(imperative handle) 같은 인터페이스로 래퍼와 통신하거나, 더 단순하게 — 폼이 `mode: 'standalone' | 'embedded'` prop을 받아 `standalone`이면 지금처럼 자체 액션바, `embedded`면 액션바 없이 `useImperativeHandle`로 `submit()` 노출.
  - 결정: **`forwardRef` + `useImperativeHandle`로 `{ submit(), isDirty() }` 노출**. 편집 라우트(`/records/:type/:id/edit`)는 폼을 `standalone`으로 직접 렌더(자체 액션바), 신규는 래퍼가 `embedded`로 렌더.
- 편집 모드 데이터 로딩: 현재 `api.getFuel().then(records => records.find(...))` — 유지. (전체조회 함수 남겨두는 이유.)
- `navigate` 목적지: `/records`.

### 7.3 편집 라우트

`/records/fuel/:id/edit` → `<FuelForm mode="standalone" />`. `maintenance`, `other` 동일. 탭 없음.

- `.topbar`, `.topbg` — 양식/설정에서 계속 쓰이므로 유지. `.topbar-home`은 Home 전용이었으므로 제거. Home/Records용으로 콘텐츠 상단 여백 클래스가 필요하면 `.content`에 `--safe-top` 반영하는 변형 추가.

- `.car-profile h1`(번호판) 관련 규칙 제거.
- `.section-footer` 규칙은 설정에서 재사용하므로 유지.
- `.bottom-nav` 폭(현재 `275px`, 4칸 기준) — 3칸에 맞게 재조정 여부 확인(구현 중).
